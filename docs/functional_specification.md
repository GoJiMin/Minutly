# Minutly 기능 명세서

## 1. 문서 목적

이 문서는 Minutly PRD를 바탕으로 MVP 구현에 필요한 기능 단위의 상세 동작을 정의한다.

---

## 2. 문서 범위

본 문서는 다음 기능을 포함한다.

1. 인증 및 접근 제어
2. 회의 녹음 및 실시간 전사
3. 전사 검토 및 요약 생성
4. 임시 저장 및 최종 저장
5. 히스토리 조회
6. 저장된 회의 수정 및 삭제
7. 공통 에러 처리

---

## 3. 용어 정의

- **originTranscript**: Azure STT가 인식한 원본 전사 텍스트
- **transcript**: 사용자가 검토 및 수정한 최종 전사 텍스트
- **실시간 전사 미리보기**: 녹음 중 화면에 표시되는 최근 10개 문장
- **draft**: 녹음 중, 오류 상황, 요약 직전 복구를 위해 `localStorage`에 임시 저장되는 데이터
- **최종 저장**: 요약 완료 후 Neon Postgres에 저장되는 회의 레코드
- **meetingDate**: 캘린더 및 날짜별 목록 조회에 사용하는 서비스 기준 날짜. `createdAt`을 `Asia/Seoul` 시간대로 해석해 생성한다.

---

## 4. 공통 전제

- 서비스는 1인 사용을 전제로 한다.
- 웹 기반으로 동작한다.
- 애플리케이션은 Vercel에 배포한다.
- 음성 인식은 Azure Speech F0를 사용한다.
- 회의 데이터는 Neon Postgres에 저장한다.
- 오디오 원본은 저장하지 않는다.
- 실시간 화면에는 전체 transcript가 아니라 최근 10개 문장만 표시한다.
- MVP의 보안은 단일 로그인 정보(`id`/`password`) 인증, httpOnly 쿠키 기반 토큰, 보호 페이지/API 검증, Vercel 기본 보호 기능을 우선 사용한다.
- 앱 레벨 감사 테이블과 rate limit은 MVP 이후 확장 후보로 둔다.

## 6. FS-01 인증 및 접근 제어

### 6-1. 목적

- 1인 서비스 환경에서 외부 접근을 제한한다.
- 인증된 사용자만 보호된 페이지와 서버 기능에 접근할 수 있도록 한다.
- 인증 관련 민감 정보가 클라이언트에 노출되지 않도록 한다.

### 6-2. 진입 조건

- 사용자가 서비스에 최초 접속한다.
- 사용자가 보호된 페이지 또는 보호된 서버 요청을 시도한다.

### 6-3. 사용자 흐름

1. 사용자는 로그인 정보 입력 화면을 본다.
2. 사용자는 `id`와 `password`를 입력하고 제출한다.
3. 서버는 전달받은 `id`와 `password`를 환경 변수에 저장된 인증 정보와 비교해 검증한다.
4. 검증 성공 시 서버는 사용자를 정상 사용자로 판단하고 인증 토큰을 발급한다.
5. 발급된 토큰은 이후 보호된 페이지 접근과 서버 요청 검증에 사용된다.
6. 인증된 사용자는 서비스 본 화면으로 진입할 수 있다.
7. 인증되지 않은 사용자가 보호된 페이지에 접근하면 Proxy 단계에서 로그인 페이지로 리다이렉트된다.
8. 보호된 Route Handler 요청은 Proxy 검증과 별도로 서버 내부에서 토큰 유무와 유효성을 다시 검증한다.
9. access token이 없거나 만료되었고 refresh token 쿠키가 있으면 클라이언트는 토큰 갱신을 시도할 수 있다.
10. 갱신할 수 없는 인증 실패 상태에서는 요청이 거부되고 사용자는 인증 화면으로 이동하거나 오류 응답을 받는다.

### 6-4. 기능 규칙

- 로그인 정보 검증은 서버에서만 수행한다.
- 클라이언트에는 실제 `id`와 `password` 값이 노출되지 않아야 한다.
- 인증 실패 응답은 `id`와 `password` 중 어느 값이 잘못되었는지 구분하지 않아야 한다.
- 인증 성공 시 서버는 후속 요청에서 식별 가능한 인증 토큰을 발급해야 한다.
- 보호된 페이지 접근 제어는 Next.js Proxy에서 수행한다.
- 보호된 Route Handler는 토큰 유무와 유효성을 별도로 검증해야 한다.
- 보호된 Route Handler는 access token이 없거나 만료되었고 refresh token 쿠키가 있는 경우 `TOKEN_EXPIRED` 응답을 반환해야 한다.
- 보호된 Route Handler는 인증 정보가 없거나 유효하지 않고 갱신 시도도 불가능한 경우 `UNAUTHORIZED` 응답을 반환해야 한다.
- `TOKEN_EXPIRED`는 사용자 안내 문구가 아니라 클라이언트가 refresh 요청 여부를 판단하기 위한 제어 신호로 사용한다.
- refresh token 검증 실패는 구체적인 실패 사유를 구분하지 않고 인증 실패로 처리한다.
- 인증이 완료되기 전에는 회의 데이터와 보호된 기능에 접근할 수 없어야 한다.
- 인증 정보가 없거나 유효하지 않으면 보호된 페이지와 서버 요청 모두 차단되어야 한다.

### 6-5. 예외

- `id` 또는 `password`가 틀린 경우
- 인증 토큰 발급에 실패한 경우
- access token이 없거나 만료되었고 refresh token 쿠키가 있는 경우
- 토큰이 없거나 유효하지 않은 상태에서 보호된 페이지에 접근한 경우
- 토큰이 없거나 유효하지 않은 상태에서 보호된 Route Handler를 호출한 경우
- refresh token이 없거나 유효하지 않은 상태에서 토큰 갱신을 요청한 경우
- 서버 인증 처리 중 예외가 발생한 경우

### 6-6. 완료 기준

- 올바른 `id`와 `password` 입력 시 인증 토큰이 발급되고 본 서비스 화면으로 진입할 수 있다.
- 잘못된 로그인 정보 입력 시 접근이 차단된다.
- 인증 토큰이 없는 사용자는 보호된 페이지 접근 시 로그인 페이지로 리다이렉트된다.
- 보호된 Route Handler 요청은 토큰 검증을 통과한 경우에만 정상 처리된다.
- access token 만료 후 refresh token이 있으면 access token을 재발급할 수 있다.
- refresh token이 없거나 유효하지 않으면 사용자는 다시 인증해야 한다.

## 7. FS-02 회의 녹음 및 실시간 전사

### 7-1. 목적

- 사용자가 회의 중 마이크 입력을 통해 회의 내용을 전사할 수 있도록 한다.

### 7-2. 진입 조건

- 인증이 완료된 상태다.
- 사용자가 메인 화면에 진입한 상태다.

### 7-3. 사용자 흐름

1. 사용자가 `녹음 시작` 버튼을 누른다.
2. 브라우저가 마이크 권한을 요청한다.
3. 권한이 허용되면 녹음을 시작한다.
4. Azure STT가 음성 인식을 수행한다.
5. 최종 인식이 완료된 문장이 발생할 때마다 transcript를 누적한다.
6. 화면에는 최근 10개 문장만 실시간 전사 미리보기로 표시한다.
7. 사용자가 `녹음 종료` 버튼을 누르면 전사를 종료한다.

### 7-4. 기능 규칙

- 실시간 화면 갱신은 Azure STT의 최종 인식 완료 이벤트 기준으로 수행한다.
- 화면에는 전체 transcript가 아니라 최근 10개 문장만 보여준다.
- 전체 transcript는 내부적으로 누적 관리한다.
- 실시간 미리보기에는 `[녹음 중단 구간]` 마커도 포함될 수 있다.

### 7-5. UI 요소

- 녹음 시작 버튼
- 녹음 종료 버튼
- 현재 상태 표시 영역
- 실시간 전사 미리보기 영역

### 7-6. 예외

- 마이크 권한 거부
- 마이크 장치 없음
- STT 서비스 오류
- 네트워크 오류로 인한 전사 중단

### 7-7. 완료 기준

- 사용자가 녹음을 시작하고 종료할 수 있다.
- 전사 결과가 누적된다.
- 화면에는 최근 10개 문장만 표시된다.

## 8. FS-03 전사 검토 및 요약 생성

### 8-1. 목적

- 녹음 종료 후 사용자가 transcript를 검토 및 수정하고, 이를 기반으로 요약 결과를 생성할 수 있도록 한다.

### 8-2. 진입 조건

- 녹음이 종료된 상태다.
- 누적된 transcript가 존재한다.

### 8-3. 사용자 흐름

1. 녹음 종료 후 transcript review 화면으로 이동한다.
2. 사용자는 originTranscript 또는 transcript를 확인한다.
3. 사용자는 오타, 누락 구간, 잘못 인식된 부분을 수정한다.
4. 사용자는 제목 입력란에 회의 제목을 입력한다.
5. 제목과 transcript가 모두 준비된 경우 사용자는 `요약 생성` 버튼을 누를 수 있다.
6. 서비스는 요약 요청 직전에 현재 title, originTranscript, transcript를 복구용 draft snapshot으로 저장한다.
7. 서비스는 수정된 transcript를 요약 AI에 전달한다.
8. 요약 결과로 `총 회의 요약`, `주요 사항`을 생성한다.
9. 요약 결과가 생성되면 title, transcript, summary, keyPoints를 포함한 최종 회의 데이터를 즉시 DB에 저장한다.
10. 저장이 성공하면 결과 화면으로 전환한다.

### 8-4. 기능 규칙

- 요약은 사용자가 최종 확인한 transcript 기준으로 생성한다.
- 결과 섹션은 다음 두 개로 고정한다.
  - 총 회의 요약
  - 주요 사항
- 제목은 요약 생성 전에 사용자가 직접 입력한다.
- 제목 형식은 `[YYYY-MM-DD. 요일] - 사용자 입력 제목`이다.
- 제목의 날짜 prefix는 `meetingDate`를 기준으로 생성한다.
- 제목이 비어 있으면 요약 생성을 진행할 수 없다.
- 요약 결과가 생성되면 별도 제목 입력 단계 없이 즉시 최종 DB 저장을 수행한다.
- 요약 요청 직전에는 전체 화면 에러에 대비해 현재 편집 상태를 draft snapshot으로 저장한다.
- 요약 실패는 녹음 중단과 다르게 처리하며, `[녹음 중단 구간]` 마커를 삽입하지 않는다.

### 8-5. UI 요소

- transcript 편집 영역
- 제목 입력 영역
- 요약 생성 버튼
- 요약 생성 중 로딩 상태 표시

### 8-6. 예외

- transcript가 비어 있는 경우
- transcript가 너무 짧은 경우
- 요약 생성 실패
- 제목 미입력

### 8-7. 완료 기준

- 사용자가 transcript를 수정할 수 있다.
- 사용자가 제목을 입력할 수 있다.
- 요약 결과가 두 섹션으로 생성된다.

## 9. FS-04 임시 저장 및 최종 저장

### 9-1. 목적

- 회의 중 데이터 유실을 방지하고, 완료된 회의 데이터를 영속적으로 저장한다.

### 9-2. 진입 조건

- 녹음이 시작되었거나, 요약 생성이 완료되었다.

### 9-3. 사용자 흐름

1. 녹음 중 transcript 초안이 1분 단위로 `localStorage`에 임시 저장된다.
2. 녹음 종료 시 최신 transcript를 한 번 더 임시 저장한다.
3. 오류 발생 시 현재 transcript를 즉시 임시 저장한다.
4. 사용자가 `요약 생성` 또는 `다시 요약`을 실행하기 직전에 현재 편집 상태를 draft snapshot으로 저장한다.
5. 사용자가 제목 입력과 transcript 검토를 마친 뒤 요약 생성을 완료한다.
6. 서비스는 요약 결과를 받은 즉시 최종 회의 데이터를 Neon Postgres에 저장한다.
7. 저장이 성공하면 관련 draft를 제거한다.

### 9-4. 기능 규칙

- 임시 저장은 draft 용도이며 `localStorage`를 사용한다.
- draft는 녹음 중 데이터 유실 방지와 요약 직전 편집 상태 복구를 모두 지원해야 한다.
- 요약 직전 draft snapshot에는 최소 title, originTranscript, transcript, 현재 단계, 기존 회의 수정 여부를 판단할 수 있는 정보가 포함되어야 한다.
- 최종 저장은 Neon Postgres의 `meetings` 레코드를 사용한다.
- 회의 1건당 DB 레코드 1개를 저장한다.
- `id`는 날짜나 시간 문자열에 의존하지 않는 DB 레코드 고유 식별자다.
- `meetingDate`는 최초 저장 시 `createdAt`을 `Asia/Seoul` 시간대로 해석해 생성한다.
- `createdAt`과 `updatedAt`은 최초 저장 시 같은 값으로 저장한다.
- 수정 저장 시 `createdAt`과 `meetingDate`는 유지한다.
- 수정 저장 시 `updatedAt`을 갱신한다.
- 최종 DB 저장이 성공하기 전까지 관련 draft를 제거하지 않는다.

### 9-5. 저장 스키마

- `id`
- `title`
- `meetingDate`
- `createdAt`
- `updatedAt`
- `originTranscript`
- `transcript`
- `summary`
- `keyPoints`

### 9-6. 예외

- localStorage 저장 실패
- draft snapshot 저장 실패
- DB 저장 실패

### 9-7. 완료 기준

- 녹음 중 draft가 임시 저장된다.
- 요약 요청 직전에 복구용 draft snapshot이 저장된다.
- 요약 완료 후 최종 DB 저장이 가능하다.
- 저장 성공 시 draft가 제거된다.

## 10. FS-05 히스토리 조회

### 10-1. 목적

- 사용자가 날짜를 기준으로 저장된 회의를 쉽게 탐색하고 다시 확인할 수 있도록 한다.

### 10-2. 진입 조건

- 사용자가 헤더의 `기록` 메뉴를 통해 히스토리 페이지로 이동한다.
- 저장된 회의가 없어도 히스토리 페이지에는 진입할 수 있어야 한다.

### 10-3. 사용자 흐름

#### A. 저장된 회의가 있는 경우

1. 사용자가 헤더의 `기록` 메뉴를 눌러 히스토리 페이지에 진입한다.
2. 좌측 상단에서 캘린더를 본다.
3. 회의가 존재하는 날짜는 강조 표시된다.
4. 사용자가 날짜를 선택한다.
5. 좌측 하단에 해당 날짜의 회의 목록이 표시된다.
6. 사용자가 회의 하나를 선택한다.
7. 우측 상세 영역에 해당 회의의 상세 내용을 표시한다.

#### B. 저장된 회의가 없는 경우

1. 사용자가 헤더의 `기록` 메뉴를 눌러 히스토리 페이지에 진입한다.
2. 서비스는 저장된 회의가 없음을 확인한다.
3. 화면에는 `아직 저장된 회의 기록이 없어요.`와 같은 빈 상태 메시지를 표시한다.
4. 사용자는 메인 화면으로 이동할 수 있는 버튼을 볼 수 있다.

### 10-4. 기능 규칙

- 히스토리 페이지는 저장된 회의 유무와 관계없이 항상 접근 가능해야 한다.
- 히스토리의 1차 그룹 기준은 `meetingDate`다.
- 캘린더의 날짜 셀은 `meetingDate` 기준으로 회의 존재 여부를 표시한다.
- 월별 캘린더 조회는 조회 대상 월의 시작일 이상, 다음 달 시작일 미만의 `meetingDate` 범위 조회로 처리한다.
- 같은 날짜에 여러 회의가 있으면 좌측 하단 목록에서 `updatedAt` 내림차순으로 정렬한다.
- 목록에는 최소 제목과 시간 정보를 표시한다.
- 상세 화면에는 제목, 회의 날짜, 생성 시각, 수정 시각, transcript, summary, keyPoints를 보여준다.

### 10-5. UI 요소

- 헤더의 `기록` 메뉴
- 좌측 1/3 영역
  - 상단 캘린더 영역
  - 하단 날짜별 회의 목록 영역
- 우측 2/3 영역
  - 선택 회의 상세 영역
- 빈 상태 메시지 영역
- 메인 화면 이동 버튼

### 10-6. 예외

- 선택한 날짜에 회의가 없는 경우
- DB 조회 실패
- 상세 로딩 실패

### 10-7. 완료 기준

- 사용자는 헤더의 `기록` 메뉴를 통해 항상 히스토리 페이지에 진입할 수 있다.
- 저장된 회의가 없는 경우 빈 상태 메시지와 메인 이동 버튼을 볼 수 있다.
- 사용자는 캘린더에서 회의가 있는 날짜를 확인할 수 있다.
- 선택한 날짜의 회의 목록을 볼 수 있다.
- 선택한 회의의 상세 내용을 확인할 수 있다.

## 11. FS-06 저장된 회의 수정 및 삭제

### 11-1. 목적

- 저장된 회의의 transcript를 수정해 재요약하거나, 불필요한 회의를 삭제할 수 있도록 한다.

### 11-2. 진입 조건

- 사용자가 FS-05 히스토리 조회 기능에서 특정 회의를 선택한 상태다.
- 선택된 회의의 상세 내용이 화면 우측 2/3 영역에 표시되고 있다.

### 11-3. 사용자 흐름

1. 사용자가 FS-05 히스토리 조회 기능에서 특정 회의를 선택한다.
2. 선택된 회의의 상세 내용이 화면 우측 2/3 영역에 표시된다.
3. 상세 영역 상단에는 액션 버튼 그룹이 표시된다.
   - `편집`
   - `다시 요약`
   - `삭제`

#### A. transcript 수정 및 재요약

4. 사용자가 `편집` 버튼을 눌러 transcript 편집 상태로 진입한다.
5. 사용자가 transcript를 수정한다.
6. 서비스는 현재 transcript가 마지막 저장본과 다른지 비교해 변경 여부를 판단한다.
7. 변경 사항이 있는 경우에만 `다시 요약` 버튼을 활성화한다.
8. 사용자가 `다시 요약` 버튼을 누른다.
9. 서비스는 수정된 transcript 기준으로 요약을 다시 생성한다.
10. summary, keyPoints, updatedAt을 갱신한다.
11. 같은 회의 레코드에 갱신 저장한다.

#### B. 회의 삭제

4. 사용자가 `삭제` 버튼을 누른다.
5. 서비스는 삭제 확인 모달을 표시한다.
6. 삭제 확인 모달은 삭제 후 복구할 수 없음을 안내한다.
7. 사용자가 삭제를 확정한다.
8. 해당 회의 레코드를 삭제한다.
9. 히스토리 목록과 상세 화면을 갱신한다.

### 11-4. 기능 규칙

- FS-06 기능은 FS-05에서 회의를 선택한 경우에만 사용할 수 있다.
- 저장된 회의의 상세 조회, 수정, 삭제 대상은 회의 `id`로 식별한다.
- 날짜는 히스토리 목록 조회를 위한 필터로만 사용한다.
- 수정의 범위는 transcript 수정 후 재요약까지로 한정한다.
- summary 또는 keyPoints 직접 편집은 지원하지 않는다.
- 상세 영역 상단에는 `편집`, `다시 요약`, `삭제` 버튼을 함께 제공한다.
- `다시 요약` 버튼은 transcript가 마지막 저장본과 달라진 경우에만 활성화한다.
- 편집 상태에 진입했더라도 실제 변경 사항이 없으면 `다시 요약` 버튼은 비활성 상태를 유지한다.
- 재요약 시 기존 회의 레코드를 갱신한다.
- transcript 수정 후 재요약이 완료되면 `updatedAt`을 갱신한다.
- 삭제는 되돌릴 수 없는 동작으로 취급한다.
- 삭제 전에는 반드시 별도 확인 모달을 통해 사용자 확인을 받아야 한다.

### 11-5. UI 요소

- 상세 영역 상단 액션 버튼 그룹
  - 편집 버튼
  - 다시 요약 버튼
  - 삭제 버튼
- transcript 편집 영역
- 삭제 확인 모달

### 11-6. 예외

- 재요약 실패
- 수정 저장 실패
- 삭제 실패

### 11-7. 완료 기준

- 사용자가 저장된 회의를 선택하면 우측 상세 영역에서 내용을 확인할 수 있다.
- 상세 영역 상단에서 편집, 다시 요약, 삭제 버튼을 확인할 수 있다.
- transcript 변경이 있는 경우에만 다시 요약 버튼이 활성화된다.
- 사용자가 저장된 transcript를 수정하고 재요약할 수 있다.
- 사용자가 저장된 회의를 삭제할 수 있다.

## 12. FS-07 공통 에러 처리

### 12-1. 목적

- 기능별 오류 상황에서 사용자가 현재 문제를 이해하고 다음 행동을 선택할 수 있도록 한다.

### 12-2. 공통 원칙

- 오류 메시지는 사용자가 이해할 수 있는 표현이어야 한다.
- 가능한 경우 기존 입력 데이터는 유지한다.
- 사용자가 재시도 가능한 액션을 제공한다.
- 회의 중 오류 발생 시 transcript 유실을 최소화한다.
- 예상 가능한 기능 실패와 예상하지 못한 전체 화면 에러를 구분해 처리한다.
- 전체 화면 에러가 발생해도 요약 직전 편집 상태를 복구할 수 있어야 한다.

### 12-3. 주요 에러 유형

- 인증 실패
- 마이크 권한 거부
- 마이크 장치 없음
- STT 연결/인식 실패
- 녹음 중단
- 요약 실패
- 저장 실패
- 삭제 실패
- 예상하지 못한 런타임 에러로 인한 전체 화면 에러

### 12-4. 공통 복구 흐름

- 녹음 중 오류: 현재 transcript 임시 저장 → 오류 안내 → 다시 녹음 시작
- 요약 실패: title, transcript 유지 → 다시 요약 또는 transcript 수정 가능
- 요약 중 전체 화면 에러: draft snapshot 유지 → 에러 화면에서 임시 내용 복구 → transcript review 상태로 복귀
- 저장 실패: draft 유지 → 다시 저장/다시 요약 가능
- 삭제 실패: 오류 메시지 표시 → 다시 삭제 가능

### 12-5. 전체 화면 에러 복구 UX

- 요약 요청 직전 저장한 draft snapshot이 존재하면 에러 화면에서 복구 액션을 제공한다.
- 에러 화면에는 다음 액션을 제공할 수 있다.
  - `임시 내용 복구`
  - `다시 시도`
  - `메인으로 이동`
- `임시 내용 복구`를 선택하면 title, originTranscript, transcript를 복구하고 transcript review 화면으로 이동한다.
- 전체 화면 에러 복구는 녹음 중단 복구와 별도의 흐름으로 처리한다.
- 전체 화면 에러가 발생했더라도 `[녹음 중단 구간]` 마커는 삽입하지 않는다.

### 12-6. 사용자 안내 예시

- `브라우저에서 마이크 권한을 허용해주세요.`
- `녹음이 중단되었습니다. 다시 녹음을 시작해주세요.`
- `중간에 일부 누락된 내용이 있을 수 있으니 요약 전에 확인해주세요.`
- `요약 생성에 실패했습니다. 다시 시도해주세요.`
- `문제가 발생했어요. 편집 중인 내용은 임시 저장되어 있어요.`
- `저장에 실패했습니다. 다시 시도해주세요.`
- `삭제에 실패했습니다. 다시 시도해주세요.`

## 13. 상태별 기능 맵

| 상태                | 가능 액션                                  | 비고                         |
| ------------------- | ------------------------------------------ | ---------------------------- |
| `idle`              | 녹음 시작                                  | 인증 완료 상태               |
| `recording`         | 녹음 종료                                  | 실시간 미리보기 표시         |
| `transcript_review` | transcript 수정, 제목 입력, 요약 생성      | 전체 transcript 표시         |
| `summarizing`       | 대기                                       | 중복 요청 방지               |
| `completed`         | 결과 확인, transcript 재수정, 재요약, 삭제 | 저장된 회의도 동일 흐름 적용 |
| `error`             | 재시도, 다시 녹음 시작, 임시 내용 복구     | 오류 유형에 따라 액션 차이   |
