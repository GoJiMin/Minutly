## Phase 0. Next.js 앱 실행과 배포 준비

- 진행: 완료
- 해결할 문제: 화면과 API를 만들기 전에 앱 실행, 테스트, 배포 준비가 가능해야 한다.
- 만들 것:
  - Next.js와 TypeScript로 실행되는 웹 앱
  - 테스트를 실행할 수 있는 Jest와 React Testing Library 설정
  - Vercel 배포와 Neon Postgres 연결에 필요한 환경 변수 준비
- 완료 기준:
  - 개발 서버를 실행할 수 있다.
  - 기본 페이지에 접근할 수 있다.
  - 테스트 명령을 실행할 수 있다.
  - Vercel에서 배포를 생성할 수 있다.
  - Neon Postgres 접속 문자열을 앱에서 사용할 수 있다.

## Phase 1. 공통 API, 에러, 날짜, localStorage 유틸

- 진행: 완료
- 해결할 문제: API 요청, 에러 응답, 날짜 계산, 브라우저 저장소 사용이 화면마다 반복되면 개발 속도와 일관성이 떨어진다.
- 만들 것:
  - API 요청 유틸
  - API 에러 응답 파서
  - 서버 에러 응답 생성 유틸
  - 요청 body, query, route parameter 검증 유틸
  - 날짜 포맷과 월별 조회 날짜 계산 유틸
  - localStorage 읽기, 쓰기, 삭제 유틸
- 완료 기준:
  - API 성공 응답과 에러 응답을 읽고 화면에서 분기할 수 있다.
  - 잘못된 요청 값을 서버에서 검증할 수 있다.
  - 회의 날짜와 월별 조회 날짜를 계산할 수 있다.
  - 브라우저 localStorage에 임시 데이터를 저장하고 다시 읽을 수 있다.

---

## Phase 2. 로그인과 보호 페이지/API

- 진행: 완료
- 해결할 문제: 1인 사용 서비스라도 외부 사용자가 회의 데이터와 서버 API에 접근하면 안 된다.
- 만들 것:
  - 로그인 화면
  - 로그인 API
  - access token과 refresh token 쿠키 발급
  - 보호 페이지 접근 차단
  - 보호 API 인증 확인
  - access token 만료 시 refresh token으로 재발급하는 클라이언트 요청
- 완료 기준:
  - 올바른 로그인 정보를 입력하면 메인 화면으로 이동한다.
  - 잘못된 로그인 정보를 입력하면 로그인이 거부된다.
  - 로그인하지 않은 사용자는 보호 페이지에 접근할 수 없다.
  - 보호 API는 인증된 요청에만 응답한다.
  - access token이 만료되면 refresh token으로 한 번 재요청할 수 있다.

---

## Phase 3. 회의 DB 저장과 날짜별 조회

- 진행: 완료
- 해결할 문제: 회의 기록은 새로고침이나 재접속 이후에도 남아 있어야 하고, 날짜별로 다시 찾을 수 있어야 한다.
- 만들 것:
  - `meetings` 테이블
  - 회의 생성 API
  - 회의 상세 조회 API
  - 회의 수정 API
  - 회의 삭제 API
  - 회의가 있는 날짜 목록 API
  - 특정 날짜의 회의 목록 API
- 완료 기준:
  - 회의 1건을 DB 레코드 1개로 저장할 수 있다.
  - 회의 id로 상세 내용을 조회할 수 있다.
  - 회의 id로 내용을 수정하고 삭제할 수 있다.
  - 특정 월에서 회의가 있는 날짜를 조회할 수 있다.
  - 특정 날짜의 회의 목록을 조회할 수 있다.

---

## Phase 4. Speech token, AI 요약, meetings API

- 진행: 완료
- 해결할 문제: 브라우저는 Azure Speech 리소스 키와 AI API 키를 직접 알면 안 되고, 회의 저장 API는 인증된 사용자만 호출할 수 있어야 한다.
- 만들 것:
  - Azure Speech token 발급 API
  - transcript를 보내 summary와 keyPoints를 받는 AI 요약 API
  - 회의 생성, 조회, 수정, 삭제 API
  - 보호 API 인증 확인
- 완료 기준:
  - 클라이언트는 Azure Speech token과 endpoint를 받을 수 있다.
  - 클라이언트는 transcript를 보내 summary와 keyPoints를 받을 수 있다.
  - 클라이언트는 회의 저장, 조회, 수정, 삭제 요청을 보낼 수 있다.
  - 보호 API는 로그인한 사용자만 사용할 수 있다.

---

## Phase 5. 회의 녹음과 STT 전사

- 진행: 완료
- 해결할 문제: 사용자는 회의 중 메모에 집중하지 않고, 마이크로 들어온 대화를 텍스트로 모을 수 있어야 한다.
- 만들 것:
  - 녹음 시작, 일시 정지, 재개, 종료 버튼
  - 녹음 시간 표시
  - Azure Speech SDK를 사용한 한국어 STT
  - 최근 전사 미리보기
  - 입력 마이크 선택
  - 마이크 권한 안내
  - 마이크 장치 오류 안내
  - 녹음 중 transcript와 녹음 시간 임시 저장
- 완료 기준:
  - 사용자는 녹음을 시작, 일시 정지, 재개, 종료할 수 있다.
  - 사용자는 녹음에 사용할 마이크를 선택할 수 있다.
  - 녹음 중 인식된 문장이 transcript로 누적된다.
  - 녹음 중 최근 인식 문장을 화면에서 확인할 수 있다.
  - 마이크 권한이 없으면 브라우저에서 권한을 허용하는 방법을 볼 수 있다.
  - 마이크 장치를 사용할 수 없으면 원인과 다음 행동을 볼 수 있다.
  - 녹음 중인 transcript와 녹음 시간은 60초마다 저장된다.

---

## Phase 6. 전사 검토, 제목 입력, AI 요약, 회의 저장

- 진행: 완료
- 해결할 문제: STT 결과에는 오타와 누락이 있을 수 있으므로, AI 요약 전에 사용자가 전사 내용을 확인하고 수정할 수 있어야 한다.
- 만들 것:
  - 녹음 종료 후 전체 전사 내용 확인 화면
  - 전사 내용 수정 입력 영역
  - 회의 제목 입력 영역
  - 요약 생성 버튼
  - 요약 생성 중 표시
  - 요약 결과 표시
  - 요약 결과와 전사 내용을 회의로 저장하는 요청
- 완료 기준:
  - 녹음 종료 후 전체 전사 내용을 확인할 수 있다.
  - 사용자는 전사 내용을 수정할 수 있다.
  - 사용자는 회의 제목을 입력할 수 있다.
  - 사용자는 수정된 전사 내용으로 AI 요약을 생성할 수 있다.
  - 요약 결과는 총 회의 요약과 주요 사항으로 표시된다.
  - 요약 결과와 전사 내용은 회의 기록으로 저장된다.
  - 요약 또는 저장이 실패해도 제목과 전사 내용은 화면에 남아 있다.

---

## Phase 7. 히스토리 캘린더, 날짜별 목록, 회의 상세

- 진행: 완료
- 해결할 문제: 저장된 회의를 다시 찾기 어렵다면 회의록으로 사용할 수 없다.
- 만들 것:
  - 히스토리 화면
  - 회의가 있는 날짜를 표시하는 캘린더
  - 선택한 날짜의 회의 목록
  - 선택한 회의의 상세 내용
  - 저장된 회의가 없을 때 표시할 안내
- 완료 기준:
  - 사용자는 히스토리 화면에 진입할 수 있다.
  - 사용자는 회의가 있는 날짜를 확인할 수 있다.
  - 사용자는 날짜를 선택해 해당 날짜의 회의 목록을 볼 수 있다.
  - 사용자는 회의를 선택해 제목, 날짜, 요약, 주요 사항, 전사 내용을 볼 수 있다.
  - 저장된 회의가 없으면 저장된 회의가 없다는 안내를 볼 수 있다.

## Phase 8. 저장된 회의록 편집 및 삭제

- 진행: 완료
- 해결할 문제: 저장 후 제목, 회의 요약, 주요 사항이 마음에 들지 않거나 더 이상 필요 없는 회의가 생길 수 있다.
- 만들 것:
  - 저장된 회의의 제목 수정 입력 영역
  - 저장된 회의의 회의 요약 수정 입력 영역
  - 저장된 회의의 주요 사항 수정, 추가, 삭제 입력 영역
  - 제목, 회의 요약, 주요 사항 저장 버튼
  - 회의 삭제 버튼
  - 삭제 전 확인 창
- 완료 기준:
  - 사용자는 저장된 회의의 제목을 수정할 수 있다.
  - 사용자는 저장된 회의의 회의 요약을 수정할 수 있다.
  - 사용자는 저장된 회의의 주요 사항을 수정, 추가, 삭제할 수 있다.
  - 저장된 회의의 원본 전사와 최종 전사는 읽기 전용으로 표시된다.
  - 저장 후 AI 요약 재생성은 제공하지 않는다.
  - 사용자는 삭제 전 확인 창을 보고 회의를 삭제할 수 있다.
  - 회의 수정 또는 삭제 후 히스토리 화면은 최신 회의 데이터를 보여준다.

---

## Phase 9. 회의별 개인 메모 저장

- 진행: 완료
- 해결할 문제: 회의 요약, 주요 사항, 원문과 별도로 사용자가 회의별 개인 메모를 남길 수 있어야 한다.
- 만들 것:
  - `meeting_memos` 테이블
  - 개인 메모 목록 조회 API
  - 개인 메모 추가 API
  - 개인 메모 삭제 API
  - 회의 상세 메모 패널의 서버 데이터 연결
  - 개인 메모 빈 상태 문구
  - 개인 메모 추가 실패 시 입력값 복구
  - 개인 메모 삭제 실패 시 목록 복구
- 완료 기준:
  - 사용자는 선택한 회의의 개인 메모를 오래된 항목부터 볼 수 있다.
  - 개인 메모가 없으면 빈 상태 문구를 볼 수 있다.
  - 사용자는 한 줄 입력란에서 Enter로 개인 메모를 추가할 수 있다.
  - 개인 메모 본문은 1자 이상 500자 이하만 저장할 수 있다.
  - 회의 1건당 개인 메모는 최대 50개까지 저장할 수 있다.
  - 사용자는 개인 메모를 즉시 삭제할 수 있다.
  - 회의 삭제 시 해당 회의의 개인 메모도 함께 삭제된다.
  - 개인 메모 조회, 추가, 삭제 실패 시 사용자는 다시 시도할 수 있다.

---

## Phase 10. 요약/저장/조회 실패 후 입력 유지와 재시도

- 진행: 완료
- 해결할 문제: 요약, 저장, 조회 실패가 사용자가 입력한 제목과 전사 내용을 잃게 만들면 안 된다.
- 만들 것:
  - 요약 실패 안내
  - 저장 실패 안내
  - 조회 실패 안내
  - 다시 시도 버튼
  - 저장 전 제목과 전사 내용 임시 저장
  - 임시 저장된 제목과 전사 내용 불러오기
- 완료 기준:
  - 요약이 실패해도 제목과 전사 내용은 화면에 남아 있다.
  - 저장이 실패해도 사용자는 다시 저장을 시도할 수 있다.
  - 회의 조회가 실패하면 사용자는 다시 조회하거나 다른 화면으로 이동할 수 있다.
  - 화면 오류가 발생해도 임시 저장된 제목과 전사 내용을 다시 확인할 수 있다.

---

## Phase 11. 배포 환경 사용자 시나리오 검증

- 진행: 완료
- 해결할 문제: 로컬 개발 환경에서 동작한 로그인, STT, AI 요약, DB 저장이 배포 환경에서도 동작해야 한다.
- 만들 것:
